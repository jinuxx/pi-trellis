# 跨层检查指南

## 什么时候使用

当一个功能同时影响 API、Service、Repository/Mapper、数据库、DTO/VO、配置或外部接口时，先完成本指南，再开始编码。

## 先画数据流

```text
输入
→ 结构校验
→ 类型/单位/格式转换
→ Service 业务规则
→ 权限与数据范围
→ 持久化或外部调用
→ 查询/聚合
→ DTO/VO 映射
→ 统一响应
```

对每条边界写清楚：

- 输入和输出类型。
- 必填、`null`、空集合和默认值语义。
- 字段格式、单位、精度和时区。
- 错误类型、响应形式和是否允许降级。
- 权限、租户、数据范围和敏感字段规则。
- 事务边界、缓存失效和事件/审计时机。

## 契约检查表

| 边界 | 重点检查 |
|---|---|
| API ↔ Service | 参数类型、校验责任、响应和异常 |
| Service ↔ Database | 字段映射、空值、逻辑删除、事务 |
| Service ↔ External API | 超时、重试、状态码、解析和降级 |
| Database ↔ DTO/VO | 单位、精度、枚举、脱敏和分页 |
| 配置 ↔ Runtime | 默认值、环境覆盖、缺失配置和启动行为 |

## 常见错误

### 隐式格式假设

数据库存储值、Service 转换值和 API 展示值必须显式定义，不能让每一层自行猜测格式或单位。

### 分散校验

结构校验可以在 Controller，业务校验必须由 Service 统一拥有。不要让多个 Controller 或 Mapper 分别实现不同版本的同一业务规则。

### 泄漏持久化模型

Entity 不应自动成为公开响应；需要展示字段、脱敏、字典转换或单位转换时，在明确的 DTO/VO 或 Service 边界完成。

### 只修复一个消费者

修改字段、状态、错误或响应格式后，必须搜索全部生产代码、测试、迁移、配置和文档消费者。

### 失败路径不一致

交互路径、批量路径、定时任务和快捷路径必须具有同等的参数校验、权限、错误处理和日志质量。

## 实现前清单

- [ ] 已列出受影响的所有层和消费者。
- [ ] 已定义字段、类型、单位、空值和错误契约。
- [ ] 已确认权限、数据范围、事务和缓存边界。
- [ ] 已搜索所有旧字段、旧响应和相同解析逻辑。
- [ ] 已决定哪些逻辑只保留在一个层中。

## 实现后清单

- [ ] 正常、空值、重复、越权和失败路径均已验证。
- [ ] 所有消费者仍能正确解析结果。
- [ ] 数据库迁移、Entity、Mapper、Service 和 VO 一致。
- [ ] 日志包含必要上下文且没有敏感信息。
- [ ] 测试或手工验证覆盖跨层契约，而不是只覆盖单个方法。
