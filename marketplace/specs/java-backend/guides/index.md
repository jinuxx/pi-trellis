# 后端思考指南

## 作用

这些指南用于决定“改之前要想什么”，不替代 `backend/` 中的实现契约。需要具体文件路径、接口格式、错误矩阵或测试要求时，继续阅读对应的后端规范。

## 可用指南

| 指南 | 触发时机 |
|---|---|
| [代码复用](./code-reuse-thinking-guide.md) | 新建 helper、工具、校验、常量、映射或响应逻辑 |
| [跨层检查](./cross-layer-thinking-guide.md) | 同时修改 API、Service、数据库、VO、配置或外部接口 |

## 快速触发条件

阅读跨层指南：

- [ ] 一个功能同时触及三个或以上层次。
- [ ] 不确定逻辑应该放在 Controller、Service 还是 Mapper。
- [ ] 修改了字段、状态、单位、响应格式或异常契约。
- [ ] 修改了共享数据、缓存、配置或外部接口。

阅读代码复用指南：

- [ ] 准备新建 helper、工具方法或常量。
- [ ] 发现两处相似的校验、映射、SQL 或响应封装。
- [ ] 正在对多个文件做相同修改。

## 修改前规则

修改任何共享值、公共方法、表字段、响应字段或模板前，先搜索：

1. 定义位置。
2. 全部读取方和写入方。
3. 相关测试、迁移、配置和文档。
4. 其他模块是否复制了同一契约。

不要只修改当前报错路径，然后假设其他消费者会自动正确。
