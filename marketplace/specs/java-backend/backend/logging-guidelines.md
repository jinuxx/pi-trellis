# 日志规范

## 日志基础

- 使用项目已有的 SLF4J + Logback 配置；需要日志的类优先遵循现有 `@Slf4j` 或 LoggerFactory 约定。
- 不使用 `System.out`、`System.err` 或 `printStackTrace()` 代替正式日志。
- 先阅读相邻代码的日志格式、输出目标、保留策略和脱敏方式，不擅自新增日志框架或格式。

## 日志级别

- `DEBUG`：详细排障信息；默认不输出完整请求/响应和高频循环数据。
- `INFO`：重要业务节点、启动完成、外部调用成功或批处理汇总。
- `WARN`：可恢复降级、非预期输入、单个外部资源失败或重试。
- `ERROR`：操作失败、解析失败、系统异常和未处理异常。

正常的参数校验或业务拒绝不应使用 `ERROR` 刷屏。相同异常已经由全局处理器记录时，其他层只在增加有效上下文时再次记录。

## 日志内容

日志应包含足以定位问题的业务上下文，例如资源 ID、项目 ID、请求 URI、操作类型、时间窗口、重试次数和外部请求 ID。批量任务优先记录数量、成功数、失败数和汇总原因，不逐条打印完整成功响应。

使用参数化日志：

```java
log.info("project={} action={} result={}", projectId, action, result);
```

## 异常与堆栈

记录失败时把异常对象作为 throwable 参数传入，保留堆栈：

```java
log.error("project={} action={} failed", projectId, action, exception);
```

不要只记录 `exception.getMessage()`，也不要把同一异常在 Controller、Service、Mapper 和全局处理器重复记录为 ERROR。

## 敏感信息

禁止记录密码、Token、Cookie、验证码、完整第三方凭据、完整身份证明信息和未经脱敏的外部请求/响应。SQL、请求体和响应体只有在明确排障且确认脱敏、范围和日志量可控时才允许临时记录。

## 验证清单

- [ ] 使用项目已有 logger 配置。
- [ ] 日志级别与事件严重程度匹配。
- [ ] 异常日志保留 throwable 和业务关联标识。
- [ ] 没有敏感字段、完整凭据或无界高频输出。
- [ ] 没有与全局处理器重复的无效日志。
